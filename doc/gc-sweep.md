# Bounded sweeps and native batch deletion

`konserve.gc/sweep!` retains its existing arities and deleted-key set result. `{:collect-deleted? false}` instead returns `{:deleted-count n :batches n}`, without retaining every deleted key. `:concurrency` bounds individual deletions (default 32), `:page-size` sets metadata page size (default 1000), and `:cancel?` is a zero-argument predicate checked before enumeration and deletion groups. Dispatched work is drained before a fallback failure returns. Cancellation and errors can follow partial deletion; no rollback is promised.

`PBatchDelete` and `PBatchDeleteBackingStore` declare non-atomic batch deletion independently of atomic multi-key writes. `batch-dissoc` holds in-process per-key locks in physical-key order, rejects conditional-delete options, invokes ordinary deletion hooks for confirmed deletions, and validates that every requested key appears in exactly one of `:deleted` or `:failed`. Partial failure throws with both categories so callers can retry failed keys. A transport failure may have an unknown outcome. DefaultStore advertises this capability only for in-place backings implementing it; rename-mode backup and recovery behavior is not bypassed.

`PKeyPage` and `PKeyPageBackingStore` provide one page at a time, including empty nonterminal pages. DefaultStore uses its ordinary logical metadata reader for each physical page. The collector does not substitute backend object timestamps for Konserve last-write timestamps. `k/keys` remains available and unchanged; backends without page support retain its materialized listing behavior. Statistics-only results alone do not bound those backends' listing memory.

A scan is not a transactional snapshot. The caller must obtain the write-guard cutoff **before** marking and enforce any required coordination with root publishers for the entire mark/sweep. A timestamp cutoff does not protect old objects promoted into a root after marking. Batch deletion does not supply a distributed barrier or atomic conditional deletion.

Tests exercise native capability independence, success/missing/duplicate keys, partial and malformed responses, hooks and lock cleanup, paginated logical timestamps, empty continuation pages, bounded fallback concurrency, error propagation and cancellation. S3 implementations and live provider request-cost measurements belong to the linked backend change.
